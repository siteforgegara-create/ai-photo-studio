  prompts.ts       общий промпт + блоки 12 стилей + запреты; 5 персонажей; 6 «плохих селфи»; правки демо
  personas.ts      bench:personas   шаг A

### Безопасность и деньги
- **Ключ.** `FAL_KEY` берётся из `.env.local` (`process.loadEnvFile`, фолбэк для Node < 20.12). Ключ нигде не печатается, а любой текст перед выводом и записью в лог проходит через `redact()` (это проверено тестом). Платные команды проверяют наличие ключа до вопроса y/N.
- **Потолок $17.**
  - Глобальный учёт расходов ведётся в `bench/runs/spend.json`.
  - Перед каждым вызовом его стоимость резервируется. Сумма «потрачено + в полёте + этот вызов» не может превысить $17, в том числе при трёх параллельных запросах: все резервы идут через одну очередь.
  - План заранее показывает, какие вызовы потолок отрежет.
- **Учёт неудач.** Запрос, отклонённый на входе (4xx при отправке), считается бесплатным. Принятый fal.ai, но упавший — потраченным: так безопаснее.
- **Повторы.** До 2 повторов на сетевые ошибки. После того как задача принята, повторяется только опрос результата по тому же `request_id`, поэтому успешная генерация не оплачивается дважды.
- **Кэш.** Готовые кадры не перегенерируются (ключ: участник/модель/стиль/номер). Селфи загружаются один раз на прогон.
- **Хранение на fal.ai.**
  - Загруженные входы и результаты истекают через 1 день (`X-Fal-Object-Lifecycle-Preference`, у клиента — `expiresIn: "1d"`).
  - История запросов отключена (`X-Fal-Store-IO: 0`).
  - Перед загрузкой из селфи удаляется EXIF (включая GPS), размер ≤ 1 МП.
- **Данные не попадают в git:** `/bench/subjects/` и `/bench/runs/` добавлены в `.gitignore` первым коммитом.

### Метрики
- **Автосходство** — `@vladmandic/human` 3.3.6 (MIT) на WASM-бэкенде: детектор BlazeFace и эмбеддинг лица FaceRes (1024-d), косинус. Сравнение идёт кадр ↔ `reference.jpg` (synth) или кадр ↔ средний эмбеддинг селфи (real).
- **Проверка библиотеки здесь:**
  - лица найдены верно: 1 / 2 / 0 на фикстурах с одним, двумя и без лица;
  - сходство фото одного и того же человека 0.97–0.998;
  - ~0.5 с на кадр.
- **Брак:** нет лица, больше одного лица, лицо меньше 12% высоты кадра.
- **Базовая линия для калибровки** (`bench:score` считает её сам):
  - «тот же человек» — селфи ↔ свой эталон;
  - «разные люди» — селфи ↔ чужие эталоны.

  Без неё абсолютные числа косинуса не с чем сравнивать.
- **Слепая оценка `review.html`.**
  - Кадры каждого участника перемешаны (детерминированно) и скопированы в `review-img/` под непрозрачными id: в пути файла иначе видна модель (`…/nb2/…`). Тест проверяет, что в странице нет ни названий, ни ключей моделей.
  - Соответствие id → модель хранится в `review-key.json`.
  - На странице есть оценки «Сходство 1–5», «Качество 1–5» и флажок «Годный для продажи».
  - Оценки сохраняются в браузере автоматически; кнопка «Сохранить оценки» скачивает `ratings.json`, предыдущий файл можно загрузить обратно.
  - Страница одна, без внешних скриптов, работает офлайн.
- **Отчёт `report.md`:**
  - таблицы по моделям: всё вместе, только реальные, только синтетические;
  - разбивка по полу, возрасту и тону кожи;
  - таблица порогов автосходства: сколько кадров с оценкой ≤ 2 отсеивается и сколько кадров с оценкой ≥ 4 сохраняется;
  - рекомендации по модели для съёмки, модели для правок и порогу;
  - LoRA-контроль, апскейл, галереи лучших и худших кадров;
  - текст fal.ai о хранении файлов.

## 4. Решения и отклонения

1. **Бюджет рассчитан на 3 реальных участника** (минимум по ТЗ) и 5 синтетических.

   | Шаг | Стоимость |
   |---|---|
   | персонажи | $1.36 |
   | генерация | $13.66 |
   | апскейл | $0.06 |
   | демо (nb2) | $1.36 |
   | **итого** | **$16.44 из $17** |

   Каждый следующий реальный участник стоит **$1.44** (4 модели × 4 кадра). С 4-м участником демо уже не помещается под потолок. Чтобы взять 4–5 человек, запускайте `bench:run` с `--no-lora` (экономит $2.14) или откажитесь от одной модели. Потолок в любом случае ничего не даст превысить.
2. **Seedream 4.5 не умеет 1K:** минимальный выход ~3.7 МП (по схеме fal.ai). Он работает в 1728×2160, остальные модели — в 880×1100, чтобы помещаться в первый оплачиваемый мегапиксель. Разница в разрешении отмечена в отчёте.
3. **FLUX.2 [pro] получает 4 референса**, хотя принимает до 9: входные изображения оплачиваются помегапиксельно. 8 референсов подняли бы цену кадра с $0.09 до $0.15 и вывели бы план за бюджет. Значение задаётся одним полем `maxRefs`.
4. **Мегапиксель в цене FLUX.2 = 1024×1024 px.** Только так сходятся примеры на странице fal.ai ($0.045 за 1920×1080). Для прочих цен «за МП» берётся 1 000 000 px — это консервативно: счёт выходит чуть больше, но не меньше.
5. **Персонажи создаются моделью вне теста** — Nano Banana v1 за $0.039. Она того же семейства, что nb2 и nbpro, поэтому их результаты на синтетике могут оказаться чуть завышены. Это ещё одна причина, по которой решают реальные участники; в отчёте это отмечено.
6. **Демо: 1 кандидат на стиль** по умолчанию (`--candidates=2`, если хватает денег).
   - Демо пишет только **новые** файлы: `public/demo/headshot/<styleId>.webp`, `selfie.webp`, `public/demo/edits/*.webp`. Существующие файлы не перезаписываются.
   - Готовый фрагмент для `demo-manifest.ts` лежит в папке прогона. В git файлы добавляете вы после просмотра.
   - Героиней может быть только synth-персонаж: реальный человек командой отклоняется.
7. **Модель для правок** напрямую не измерялась (по ТЗ генерация — по селфи). Отчёт предлагает её эвристически: самая дешёвая из моделей, отстающих от лучшей по сходству не более чем на 0.3. Проверка — в `bench:demo` (5 правок через тот же автофильтр).
8. **FaceRes — метрика только для B0.** По 00-decisions для продакшена нужен отдельный сервис сравнения лиц с коммерческой лицензией. FaceRes используется здесь лишь как внутренний инструмент замера, его эмбеддинги в продукт не идут.
9. **Новые модели в каталоге fal.ai.** На дату проверки там есть Nano Banana 2.1, Seedream 5.0 Pro (только text-to-image) и FLUX 3. В тест они не включены, ТЗ их не называет. Добавить модель — одна запись в `MODELS` после проверки схемы.
10. **Связь с fal.ai отсюда не проверялась** (ключа нет, и сеть, скорее всего, закрыта). Поэтому перед полным прогоном рекомендую дешёвый смоук-тест (см. §6, шаг 3) — он проверит путь «загрузка → генерация → скачивание» за ~$0.16.

## 6. Инструкция для владельца — коротко (актуальна после правок §7)

1. `npm install`. Проверьте, что в `.env.local` есть строка `FAL_KEY=…`.
2. **Селфи.** Положите 4–8 фото каждого человека в `bench\subjects\real-01\selfies\`, `real-02\selfies\` и `real-03\selfies\` (до `real-05` влезает в бюджет). Скопируйте `bench\subjects.example.json` в `bench\subjects\subjects.json` и поправьте пол, возраст и тон кожи.
3. **Персонажи.** `npm run bench:personas -- --dry-run`, затем `npm run bench:personas` ($1.00). Посмотрите на `bench\subjects\synth-*`.
4. **Смоук-тест.** `npm run bench:run -- --only=nb21,flux3 --subjects=synth-01 --no-lora` ($0.44). Затем сверьте расход на странице Usage в fal.ai с планом: у этих двух моделей цена — оценка.
5. **Генерация.** `npm run bench:run -- --dry-run`, затем `npm run bench:run` (≈ $11.29 — без смоук-кадров).
6. **Автометрики и страница оценки.** `npm run bench:score`, затем `npm run bench:review`.
7. **Оценка.** Откройте `bench\runs\<дата>\review.html`, оцените все кадры и нажмите «Сохранить оценки». Положите `ratings.json` в ту же папку.
8. **Отчёт.** `npm run bench:report` → `bench\runs\<дата>\report.md`.
9. **Апскейл.** `npm run bench:upscale` ($0.06).
10. **Демо.** `npm run bench:demo -- --model=<победитель> --dry-run`, затем без `--dry-run`. Посмотрите `public\demo\` и добавьте в git то, что оставляете.

Подробности — в `bench/README.md`.
