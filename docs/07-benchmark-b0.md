# 07 — B0: бенчмарк моделей сходства (+ демо-набор)

**Цель.** До строительства бэкенда выяснить, какая модель через fal.ai лучше всего сохраняет лицо человека по 4–8 обычным селфи, сколько это стоит и сколько кадров уходит в брак. От результата зависят выбор модели, порог фильтра сходства (P4) и окончательные цены (M2–M4).

**Бюджет: жёсткий потолок $17** (на балансе fal.ai $20, запас — на повторы). Скрипт обязан считать расходы и останавливаться до превышения.

---

## 1. Где что выполняется

- Код пишешь ты (Claude Code) — в папке `bench/` этого репозитория.
- **Запускает владелец у себя на Windows** (`npm run bench:*`): твоя облачная среда, скорее всего, не достучится до fal.ai.
- Ключ лежит в `C:\Projects\AI-Studio_claude\.env.local` (`FAL_KEY=...`). **Никогда не читай этот файл и не выводи ключ в логи.** Скрипты подгружают его через `dotenv`/`process.loadEnvFile` и падают с понятным сообщением, если ключа нет.
- **Фото реальных людей и результаты не попадают в git:** добавь `/bench/subjects/` и `/bench/runs/` в `.gitignore` первым делом.

## 2. Участники (subjects)

```
bench/subjects/
  real-01/selfies/*.jpg        ← владелец кладёт 4–8 селфи реального человека
  real-02/ ...                 ← 3–5 реальных людей
  synth-01/                    ← создаются скриптом (шаг A)
  ...
  subjects.json                ← id, тип (real/synth), пол, возрастная группа, тон кожи (для отчёта)
```

**Шаг A — синтетические персонажи (5 шт.).** Разный пол, возраст (25–35, 35–50, 50–65) и тон кожи. Для каждого:
1. Портрет-эталон (text-to-image, нейтральный свет, фронтально).
2. Из эталона — 6 «плохих селфи» одной недорогой моделью: фронтальная камера телефона, искажение широкого угла, разное освещение (окно, лампа, вечер), ракурсы 0°/±20°, разная одежда, лёгкий шум.
3. Эталон сохраняется как `reference.jpg` — с ним считается сходство. Селфи — входные данные для тестируемых моделей.

Ограничение (вписать в отчёт): у синтетических персонажей «эталон» сам сгенерирован, их результаты оптимистичнее реальных. **Решающие — реальные участники.**

## 3. Тестируемые модели

Точные id эндпоинтов и цены **проверь по документации fal.ai** и занеси в `bench/config.ts` (поле `pricePerImage`, источник и дата проверки). Кандидаты:

| Ключ | Модель | Вход |
|---|---|---|
| `nb2` | Nano Banana 2 (Google) | все селфи как референсы (до 14) |
| `nbpro` | Nano Banana Pro | все селфи |
| `seedream` | Seedream 4.5 (или новее, если есть) | селфи как референсы |
| `flux2` | FLUX.2 Pro | 1–N референсов, сколько поддерживает |
| `lora` | **Контроль «как у конкурентов»:** быстрая LoRA-тренировка FLUX на селфи + генерация | только для 1 реального участника (дорого) |

Разрешение генерации — 1K (≈1024 px) для всех; отдельно мини-тест апскейла: 3 лучших кадра → 4K через апскейлер на fal.ai (цена и качество).

## 4. Задание генерации

Для каждого участника × модели: **2 стиля × 2 кадра = 4 кадра**. Стили — `corporate-gray` и `modern-office` (из `src/config/styles.ts`), одинаковые промпты для всех моделей, в `bench/prompts.ts`:

- общий блок: «professional headshot photo of the same person as in the reference photos, preserve exact facial features, face shape, skin tone, eye color, hairline, age; natural skin texture; head and shoulders; looking at camera; …»
- блок стиля (фон, одежда — blazer, свет);
- запреты: no beautification, no face reshaping, no extra people, no text.

Seed фиксировать там, где модель поддерживает. Каждый вызов логировать: модель, участник, стиль, время, стоимость, id запроса, ответ (без ключа).

## 5. Метрики

**Автоматические** (`bench/score.ts`):
- **Сходство лица** — косинусная близость эмбеддингов лица: кадр ↔ эталон (synth) или кадр ↔ среднее по селфи (real). Библиотека — **`@vladmandic/human`** (MIT, работает в Node, есть модель эмбеддинга лица). Веса InsightFace/ArcFace не использовать (некоммерческая лицензия).
- Технический брак: лицо не найдено / два лица / лицо слишком маленькое (тот же детектор).
- Время ответа и стоимость кадра.

**Ручная оценка — решающая** (`bench/review.html`, генерируется скриптом):
- Локальная страница: для каждого участника показываются его селфи и все кадры всех моделей вперемешку, **модель скрыта** (слепая оценка).
- Владелец ставит каждому кадру: **Сходство 1–5** («узнал бы я этого человека?») и **Качество 1–5** (артефакты, пластиковая кожа, руки, зубы), плюс флажок «годный для продажи».
- Кнопка «Сохранить оценки» скачивает `ratings.json`; владелец кладёт его в папку прогона.
- Для реальных участников желательно, чтобы оценивал сам человек на фото.

## 6. Команды

```
npm run bench:personas -- --dry-run   # шаг A: план и стоимость
npm run bench:personas                # создать синтетических персонажей
npm run bench:run -- --dry-run        # план генерации: число вызовов × цены = итог
npm run bench:run                     # генерация; можно --only=nb2,seedream --subjects=real-01
npm run bench:score                   # автометрики
npm run bench:review                  # собрать review.html
npm run bench:report                  # свод после ratings.json
```

- Каждая команда **сначала печатает план и стоимость** и запрашивает подтверждение `y/N` (флаг `--yes` для пропуска).
- **Потолок**: суммарный учтённый расход по всем прогонам хранится в `bench/runs/spend.json`; любой вызов, который выведет итог за $17, не выполняется.
- Повторный запуск не перегенерирует уже готовые кадры (кэш по ключу участник/модель/стиль/номер).
- Параллельность ≤ 3 запросов; повтор при сетевой ошибке ≤ 2 раз, без повторной оплаты успешных.
- Результаты: `bench/runs/<YYYY-MM-DD>/<subject>/<model>/<style>-<n>.jpg` + `log.jsonl`.

Ориентир стоимости (уточнить по реальным ценам в dry-run): 9 участников × 4 модели × 4 кадра ≈ $12–13, персонажи ≈ $1–2, LoRA ≈ $2–3, апскейл ≈ $0.5.

## 7. Отчёт `bench/runs/<date>/report.md` (генерируется `bench:report`)

Таблица по моделям: среднее сходство (авто), средние оценки сходства и качества (ручные), **доля годных кадров**, доля брака, среднее время, стоимость кадра и **стоимость одного годного кадра** (= цена / доля годных). Разбивка real/synth и по группам участников. Галерея: лучшие и худшие кадры каждой модели. Итоговая рекомендация по данным: модель для съёмки, модель для правок, порог автосходства, при котором отсеиваются кадры с оценкой сходства ≤ 2.

## 8. Демо-набор (после выбора модели, отдельной командой)

`npm run bench:demo -- --model=<winner>`: синтетическая героиня (новый персонаж или synth с лучшими результатами) во **всех 12 стилях** `styles.ts` + пары до/после для инструментов Studio (Background, Outfit, Retouch, Relight) моделью для правок. Прогон через тот же автофильтр сходства. Выход — `public/demo/...` в форматах и именах по `demo-manifest.ts` (1080×1350 webp), но **в git их добавляет только владелец после просмотра**. Бюджет этого шага — входит в общий потолок.

## 9. Конфиденциальность

- Фото реальных людей — только с их устного согласия на тест, не в git, не в отчётах для публикации. После завершения B0 владелец удаляет `bench/subjects/real-*`.
- Входные файлы загружаются в хранилище fal.ai только на время генерации; в отчёт внеси, что пишет fal.ai о сроке хранения загруженных файлов.

## 10. Приёмка

Код: `lint`, `typecheck`, unit-тесты расчёта стоимости и потолка, тест сборки `review.html` на фейковых данных. Dry-run по всем командам работает **без ключа** (показывает план и цены). Реальный прогон делает владелец.
